# 战斗音频测试实验场测试方案

## 1. 测试目标

验证游戏战斗场景中的音频事件能否在正确时机触发，并在状态切换、语音混音、空间定位、静音、暂停和异常条件下保持可追溯、可复现。

测试重点不是音频作品制作，而是将音频需求转化为可执行测试点，并为每个失败场景保留事件日志。

## 2. 被测对象

- 被测系统：战斗音频测试实验场
- 运行环境：Windows 11，Chrome 155
- 分辨率：桌面 1440 x 1024，移动端 390 x 844
- 音频实现：Web Audio API
- 自动化：Playwright
- 测试版本：LOCAL TESTBED 01

## 3. 测试范围

| 范围 | 内容 |
|---|---|
| 功能 | 攻击、受击、技能、语音、敌人死亡、暂停与恢复 |
| 音乐状态 | 探索BGM、战斗BGM、状态切换与切换断点 |
| 混音 | Master、Music、SFX、Voice和语音压低BGM |
| 空间音频 | 声像、距离衰减、声像反转 |
| 稳定性 | 延迟、重复播放、音量不恢复、静音泄漏 |
| 性能 | 活跃声部、峰值电平、Canvas持续渲染 |
| 兼容性 | 桌面与移动端布局、控制台异常、页面溢出 |

## 4. 音频事件

| 事件 | 总线 | 关键检查点 |
|---|---|---|
| `bgm_state_change` | MUSIC | 状态是否切换、是否记录切换前后状态 |
| `bgm_switch_gap` | FAULT | 切换断点是否被测试捕获 |
| `attack_swing` | SFX | 是否在攻击动作开始时触发 |
| `impact_hit` | SFX | 是否在命中时触发、是否受延迟影响 |
| `impact_hit_duplicate` | SFX | 重复触发故障是否可检测 |
| `skill_cast` | SFX | 技能释放音效是否触发 |
| `skill_impact` | SFX | 技能命中音效是否延迟触发 |
| `voice_start` | VOICE | 语音事件是否开始并进入VOICE总线 |
| `bgm_duck` | MIX | 语音开始后BGM是否被压下 |
| `bgm_restore` | MIX | 语音结束后BGM是否恢复 |
| `enemy_proximity` | SFX | 声像和距离增益是否符合预期 |
| `enemy_death` | SFX | 敌人死亡是否产生独立音频事件 |
| `master_mute` | SYSTEM | 静音操作是否进入事件日志 |
| `audio_suspend` | SYSTEM | 暂停是否进入事件日志 |

## 5. 风险分析

| 风险 | 影响 | 测试策略 |
|---|---|---|
| 攻击动作与命中音不同步 | 玩家无法确认攻击是否生效 | 检查事件时间差与故障延迟 |
| 快速操作导致音效叠加 | 出现爆音、声部堆积 | 连续触发并统计重复事件 |
| BGM切换存在静音间隙 | 战斗节奏断裂、沉浸感下降 | 注入断点并检查恢复事件 |
| 语音压低BGM后未恢复 | 后续音乐音量持续偏低 | 对比恢复前后混音事件 |
| 左右声像与实际位置不一致 | 玩家误判敌人方向 | 输入固定声像并核对实际应用值 |
| 静音后VOICE仍可听见 | 静音控制失效 | 注入泄漏故障并检查事件 |
| 移动端控件溢出或重叠 | 关键操作无法完成 | 390 x 844 视口自动布局检查 |

## 7. 准入与退出标准

准入标准：

- 页面可以正常加载。
- 音频上下文可以被用户操作启动。
- 所有P0测试点具备可观察事件。

退出标准：

- 30项计划用例全部通过。
- 自动测试无控制台错误。
- 桌面和移动端无页面溢出。
- 故障注入均可产生可定位证据。
- 关键事件时间线保存为JSON。

## 8. 验证边界

自动化覆盖事件触发、顺序、延迟、混音参数、声像值、布局和渲染状态。耳机实听、音量平衡主观判断、蓝牙设备切换延迟和不同声卡驱动兼容性，仍需要在真实设备上补做人工验证，不能由浏览器模拟完全替代。
