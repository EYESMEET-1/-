# 战斗音频测试实验场测试报告

## 1. 结论

测试版本完成了38项自动检查，全部通过；交互过程中共记录42条音频事件，其中14条为故障或异常验证事件。

本轮验证覆盖功能、混音、空间、性能、兼容性和六类故障注入。自动化能够稳定识别音频事件缺失、重复、延迟、混音恢复失败、声像反转和BGM切换断点。

听感类检查仍需要在耳机、扬声器和蓝牙设备上进行人工确认，本轮不对主观音质作过度声明。

## 4. 六类故障证据

### 4.1 攻击音效延迟

- 故障：`latency`
- 注入延迟：220 ms
- 事件：`latency_fault_applied`
- 证据ID：13
- 观察：命中音被延迟后仍可通过事件时间线定位。

### 4.2 命中音重复叠加

- 故障：`duplicate`
- 注入延迟：18 ms
- 事件：`impact_hit_duplicate`
- 证据ID：18和19
- 观察：额外命中声部被单独记录，未与主事件混淆。

### 4.3 BGM切换断点

- 故障：`bgmGap`
- 注入断点：360 ms
- 事件：`bgm_switch_gap`
- 证据ID：26
- 恢复事件：`bgm_state_change`
- 证据ID：27
- 观察：断点与恢复完成均有时间戳，可计算切换总耗时。

### 4.4 语音结束后BGM不恢复

- 故障：`duckStuck`
- 事件：`duck_restore_missing`
- 证据ID：34
- 观察：语音开始后记录 `bgm_duck`，超时后没有新增 `bgm_restore`，失败行为可稳定检测。

### 4.5 声像左右反转

- 故障：`panInvert`
- 原始声像：0.800
- 实际应用声像：-0.800
- 证据ID：21
- 观察：故障开关、原始输入和实际应用值均被保存。

### 4.6 静音状态语音泄漏

- 故障：`voiceLeak`
- 事件：`voice_leak_fault_applied`
- 证据ID：37
- 观察：静音后VOICE总线异常状态被记录，可继续用于混音节点级定位。

## 5. 开发期缺陷

### BUG-001 空声像值导致事件日志中断

- 严重程度：P1
- 现象：初始化BGM状态时，事件日志收到空声像值并调用数字格式化，页面运行时异常。
- 根因：日志入口直接调用 `toFixed`，未处理 `null`。
- 修复：日志字段统一转换为数字并设置零值兜底。
- 复测：启动、攻击、语音和状态切换均通过。

### BUG-002 BGM断点恢复后缺少完成事件

- 严重程度：P2
- 现象：开启BGM断点后，可以记录断点开始，但恢复完成没有独立事件。
- 根因：延迟恢复分支只重新启动音乐，没有写入状态切换事件。
- 修复：在恢复完成时写入带 `recoveredAfterGap` 标记的 `bgm_state_change`。
- 复测：断点开始与恢复完成均可被自动断言捕获。

## 8. 风险与后续验证

以下项目需要在真实设备或更接近正式游戏工程的环境中补测：

- 长时间运行下的内存、声部回收和音频线程占用。
- Unity/Wwise环境中的Event、Switch、RTPC和Bus配置验证。
